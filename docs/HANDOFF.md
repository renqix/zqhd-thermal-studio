# 面向共创者的交接

## 当前实现

本地Tiny v3核心经过原使用者实机认可。公开版延续该算法/UI，替换系统中文字形为Noto、把Mac绝对路径/指定设备绑定改成环境配置。公开字体版仅完成编译和主机测试，尚未重新刷入实机；Release据此标为预发布。

Mac完整EDSR和MCU微型学生是两条运行链路。核心代码：`web/enhancement.py`、`firmware/thermal_v2/tiny_student.h`、`tiny_weights.h`、`thermal_processing.h`。USB协议为ASCII控制+二进制原始矩阵/索引镜像，网页只有一个串口读取线程。

## 已知约束

- 探头为Heimann32×32，不可照商品说明当MLX90640；不能靠插值增加真实温度点。
- 250MHz不再提高；默认Tiny且可切回L3。原厂EEPROM不写入。
- 用户要求MIN/MAX三角每帧跟踪；曾拒绝多帧等待、位置死区和慢速动画，不宜悄悄恢复。
- 网页镜像占用USB和设备时间；默认关闭，原始和增强仍更新。
- 设备设置没有掉电保存；恢复流程见RESTORE.md。
- Tiny当前整数算子仍有优化空间，额外20ms目标未严格验证。模型卡中的合成PSNR不能用作真实分辨率宣称。

## 建议下一步

1. 开源字体版真机视觉与触摸验收。
2. 固定场景、滤波、色板、镜像开关，采集Tiny/L3同条件中位数和P95；分开传感器等待/算法/LCD/USB时间。
3. 优化整数推理循环，避免新增大堆缓存；保持Python参考与C++逐点一致。
4. 增加独立真实场景：细线、小热点、移动目标、低温差。真实数据共享前取得许可并去除隐私。
5. 如要重训，固定数据、随机状态、软件版本，保存验证集和模型SHA，再集成新权重。

原厂备份和私人历史交接不在公开仓库中；使用者必须保留自己的回退路径。不要把构建成功当作刷写成功，也不要把串口零错误当成所有手势已人工验证。
